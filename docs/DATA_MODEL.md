# Data Model

All tables live in `packages/db/src/schema/`. Conventions come from the old prototype and are kept: UUID primary keys generated by Postgres, `created_at` / `updated_at` / `deleted_at`, `metadata jsonb`, `organisation_id` on every business table with `ON DELETE CASCADE`.

Enums are Postgres enums defined next to the table that owns them.

## system.ts
- `organisations`: `name`, `slug` unique, `status` (`active|suspended`).
- `organisation_members`: `organisation_id`, `user_id` (Better Auth user), `display_name?`, `title?`, `phone?`, `invited_by?` (Better Auth user), `initial_password_set_at?`, `role` (`owner|staff`), `status` (`active|invited|suspended`). Unique `(organisation_id, user_id)`.
- `client_users`: `organisation_id`, `client_id` (FK), `user_id`, `role` (`client_admin|client_member`). Unique `(client_id, user_id)`.

## auth.ts
Generated by `npx @better-auth/cli generate` with the Drizzle adapter: `user`, `session`, `account`, `verification`. Do not hand-edit; regenerate.

## clients.ts
- `clients`: `name`, `slug` unique per organisation, `trading_name`, `email`, `phone`, `address_line1/2`, `city`, `postcode`, `country` (default `GB`), `website_url`, `industry`, `support_email` (globally unique, `<slug>@SUPPORT_EMAIL_DOMAIN`), `package_id` (FK added in Plan 3), `status` (`active|paused|archived`), `notes`.
- `client_contacts`: `client_id`, `name`, `email`, `phone`, `role`, `is_primary`.

## sites.ts
- `sites`: `client_id`, `name`, `primary_url`, `platform` (`wordpress|static|nextjs|other`), `hosting_provider` (`coolify|other`), `hosting_ref` (Coolify app UUID), `status` (`live|building|paused|archived`).
- `domains`: `client_id`, `site_id?`, `name` unique per organisation, `registrar`, `dns_provider` (`cloudflare|registrar|other`), `nameservers text[]`, `notes`, `expires_at`, `auto_renew`, `status` (`active|expiring|expired|transferring`).
- `dns_records`: `domain_id`, `type` (`A|AAAA|CNAME|MX|TXT|SRV`), `name`, `value`, `ttl`, `proxied`.

## billing.ts
- `billing_profiles`: `client_id` unique, `billing_name`, `address_line1/2`, `city`, `postcode`, `country` (default `GB`), `vat_number`, `payment_terms_days` (default 14), `stripe_customer_id?`, `preferred_method?`, `notes?`. No card or bank numbers, ever.

## activity.ts
- `activity_events`: `client_id?`, `site_id?`, `actor_kind`, `actor_id?`, `kind`, `title`, `body?`, `link?`. Index on `(client_id, created_at)`. The human-readable per-client timeline; `audit_log` remains the machine record.
- `notifications`: `user_id`, `kind`, `title`, `body?`, `link?`, `read_at?`. Index on `(user_id, read_at)`.

## support.ts
- `conversations`: `client_id`, `site_id?`, `subject`, `channel` (`portal|email|whatsapp|internal`), `status` (`open|closed`), `last_message_at`.
- `messages`: `conversation_id`, `direction` (`inbound|outbound|internal`), `author_kind` (`user|client|agent|system`), `author_id?`, `body`, `body_html?`, `external_id?` (provider message id, unique when present), `delivered_at?`.
- `tickets`: `conversation_id`, `client_id`, `site_id?`, `subject`, `category?` (`hosting|dns|content|email|ads|billing|other`), `severity` (`low|medium|high|critical`), `status` (`open|triaged|in_progress|waiting_client|resolved|closed`), `assigned_user_id?`, `escalated` bool, `escalation_reason?`, `source` (`portal|email|agent|monitor|manual`).
- `ticket_events`: `ticket_id`, `kind` (`created|status_changed|assigned|note|escalated|agent_action`), `actor_kind`, `actor_id?`, `data jsonb`.

## ads.ts
- `ad_accounts`: `client_id`, `platform` (`google|meta`), `external_id`, `name`, `currency`, `status`.
- `ad_metric_snapshots`: `ad_account_id`, `date`, `spend`, `impressions`, `clicks`, `conversions`, `conversion_value`, `cpc`, `roas`. Unique `(ad_account_id, date)`.
- `ad_reports`: `ad_account_id`, `period_start`, `period_end`, `summary_md`, `status` (`draft|approved|sent`), `agent_run_id?`, `sent_message_id?`.

## knowledge.ts
- `knowledge_articles`: `title`, `slug` unique per organisation, `body_md`, `tags text[]`, `published` bool, `search tsvector` generated from title and body with a GIN index.

## monitoring.ts
- `monitors`: `site_id`, `kind` (`http|ssl|resource`), `target`, `interval_seconds`, `enabled`, `consecutive_failures` int.
- `uptime_checks`: `monitor_id`, `checked_at`, `ok`, `status_code?`, `latency_ms?`, `error?`. Index on `(monitor_id, checked_at desc)`.
- `incidents`: `site_id`, `monitor_id?`, `ticket_id?`, `status` (`open|acknowledged|resolved`), `severity`, `title`, `summary_md?`, `opened_at`, `resolved_at?`, `agent_run_id?`.

## agents.ts
- `agent_enablement`: `agent_key`, `enabled`, `config jsonb`. Unique `(organisation_id, agent_key)`.
- `agent_runs`: `agent_key`, `trigger` (`cron|event|manual|resume`), `status` (`running|completed|awaiting_approval|failed`), `input jsonb`, `summary?`, `error?`, `tokens_in`, `tokens_out`, `started_at`, `finished_at?`.
- `agent_steps`: `run_id`, `seq`, `kind` (`llm|tool_call|tool_result|approval_requested|note`), `tool_name?`, `input jsonb`, `output jsonb`, `tokens_in?`, `tokens_out?`. Unique `(run_id, seq)`.
- `approvals`: `run_id?`, `step_id?`, `kind` (`tool_call|report_send|message_send|dns_change|content_change`), `title`, `payload jsonb`, `status` (`pending|approved|rejected`), `decided_by?`, `decided_at?`, `decision_note?`.
- `audit_log`: `actor_kind` (`user|agent|system`), `actor_id?`, `action`, `target_type`, `target_id`, `before jsonb?`, `after jsonb?`.

## Relationship summary

```
organisations ─┬─ organisation_members ── user
               ├─ clients ─┬─ client_contacts
               │           ├─ client_users ── user
               │           ├─ sites ─┬─ domains ── dns_records
               │           │         ├─ monitors ── uptime_checks
               │           │         └─ incidents ── tickets
               │           ├─ conversations ── messages
               │           ├─ tickets ── ticket_events
               │           └─ ad_accounts ─┬─ ad_metric_snapshots
               │                           └─ ad_reports
               ├─ knowledge_articles
               ├─ agent_enablement
               ├─ agent_runs ── agent_steps ── approvals
               └─ audit_log
```
